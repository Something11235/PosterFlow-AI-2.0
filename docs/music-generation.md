# 音乐创作接入

2026-10-23，北京时间。本功能属于 `AI全功能生成工作台` 本地升级版，不代表已发布或已调用真实服务商。

## 两种服务方式

- **平台积分**：服务端使用独立的 `APIMART_MUSIC_API_KEY`，只访问 `https://api.apimart.ai/v1/music`。Suno 的 v6、v6-wild、v6-mini，以及 Flow Music 的 Lyria 3 Pro、Lyria 3.5 均为每首 **2 网站积分**。原来三个图像模型的端点、Key、模型和价格不变。
- **自定义API Key**：用户填写自己的完整 HTTPS 音乐生成接口、Key、鉴权方式，必要时填写任务查询地址。支持 Bearer Token 和 x-api-key。可选预置模型，或选择“自定义模型”，填写标识、可选版本，并选择 Suno / Flow Music 参数格式。不会扣网站积分。

自定义服务须兼容本页说明的异步请求和响应结构。配置一个地址不代表能兼容任意服务商的私有协议；字段或响应结构不同的接口需要另加适配器。Key、端点和鉴权配置仅在浏览器 sessionStorage 中保存，不进入数据库、草稿或日志。

## 表单与协议

Suno 提供灵感描述、自定义歌词、纯音乐，以及可选标题、风格、人声、音频格式、目标时长、排除风格、歌词改写和权重。模式切换保留各自文本，灵感模式不发送自定义模式字段；数值 0 是有效权重。没有开放上游加倍计费的 Max 模式。

Flow Music 提供风格描述、歌词、标题、目标时长、BPM 和种子。Lyria 3 Pro 使用文档的标准 Flow 路由，不发送未经确认的版本字符串；Lyria 3.5 明确发送 `version: "lyria-3.5"`。界面中的 Pro 名称对应用户选定的标准路由，服务商账号实际模型权限仍需真实联调确认。

**目标时长默认自动**：Suno 的 `duration`、Flow Music 的 `length` 在留空时完全省略，不把空串转换成 0。填写时分别校验为 10–360 秒、1–240 秒整数；目标不保证等于实际输出时长。Flow 描述/歌词 6000 字符等未由上游公开规定的限制在界面明确标为本站上限。

平台创建任务为 `POST /v1/music/generations`，从 `data[0].task_id` 取得编号；查询为 `GET /v1/music/tasks/{task_id}`。完成状态读取 `data.status`，不根据 100% 进度推断完成。音乐从 `data.result.music[]` 读取，保留原始 1 起始索引，不固定返回两首。音频 URL 不要求以 mp3 结尾；兼容两类时长字段及 Flow 的可选 WAV 链接。

自定义模式中的查询地址须包含一次 `{task_id}`；留空则从生成接口推导同级 `tasks/{task_id}`。两个地址须同域、HTTPS，不接受 URL 凭据或查询参数。服务端解析并校验公网地址，连接时固定已验证 IP、保留 TLS 主机名验证；禁止私网、自动重定向和自动 POST 重试。

## 任务与积分

音乐采用独立 `music_jobs`，不把歌曲当图片写进 `generation_jobs`，也不受旧图片十分钟过期退款影响。

1. 一次用户意图创建一个 UUID。服务端在调用服务商之前建立持久记录；平台模式验证真实邮箱确认、账户状态和余额，并先预留 2 积分。
2. 同一所有者和请求编号只能有一条任务。参数指纹不一致返回冲突；重复 POST 返回原任务，不再次调用服务商。
3. 确认生成完成后，以实际有效音乐首数 × 2 结算。Suno 若返回两首即扣 4 积分。首数由受信任查询响应确定，浏览器不能提供可信数量、价格或成功状态。
4. 若多首结果超出可用余额，任务保持完成、计费状态为 `awaiting_balance`，不透支、不退款、不重发生成，暂不返回播放链接。补足余额后刷新原任务即可完成结算。首次确认的首数固定，避免后续响应变化重复扣费。
5. 服务商明确拒绝提交，或任务查询明确返回 failed，退回预留积分；重复或乱序查询不能重复退款，也不能回退已结算终态。
6. 请求超时、5xx、异常响应及 `unknown` 不自动退款或重新提交。没有取得上游编号的提交不确定任务，需要站长根据服务商日志对账；不能保证上游不提供幂等时的端到端 exactly-once。

平台凭据不受浏览器自定义地址或 Key 影响。数据库公开包装函数为 invoker；原子积分写入和读取权威 Auth 状态由 private 中的窄接口执行，固定空 search_path、撤销 PUBLIC/anon/authenticated 执行权，仅 service_role 可调用。表启用 RLS，前端无直接读写权限。自定义任务按认证身份、Key 与完整服务配置的不可逆摘要隔离；修改服务配置后不会混入另一服务商的任务。

## 播放、下载与保存范围

页面展示任务列表、真实状态、试听控件、歌词、音频下载和可选 WAV 下载。播放器和下载直接读取服务商返回的 HTTPS 媒体，外部请求不携带本站或服务商鉴权头。下载在浏览器流式读取，60 秒超时、80 MiB 内存预算，拒绝 HTML/JSON 错误内容；失败时可打开音频链接自行保存。

后端不转存音频，不把音乐套入原图片 12 小时清理策略。数据库只保存归属摘要、请求指纹、模型版本、任务编号、状态、计费和时间，不保存提示词、歌词、媒体 URL 或 Key。歌词和作品链接从服务商查询即时返回；没有因此扩展七天纯文本历史。上游链接有效期以服务商为准，任务记录不代表音频永久可取。

当前页面草稿仍只存内存，刷新清空；模型、参数与草稿导出均不包含服务配置。音乐任务可凭原编号在刷新后恢复，自定义模式需重新使用原服务配置；跨身份、关闭面板或页面不可见时停止相应轮询。页面停止等待不等于取消上游任务。

## 本地启用

1. 在新版目录使用独立开发 Supabase 配置，不复制原站生产 `.env` 或 `.vercel`。
2. 在开发数据库应用新增迁移 `supabase/migrations/20261022164535_music_generation.sql`，不要重跑已有生产迁移。
3. 服务端配置 `SUPABASE_URL`、`SUPABASE_SERVICE_ROLE_KEY`（或现有 Secret Key 别名）。平台音乐另配 `APIMART_MUSIC_API_KEY`，不能使用 VITE_ 前缀。
4. 登录能力使用浏览器安全的 VITE_SUPABASE_URL、VITE_SUPABASE_ANON_KEY / PUBLISHABLE_KEY。平台模式须登录并验证邮箱；自定义模式可使用访客 Key，但仍需要音乐任务数据库就绪。
5. 运行开发前端 3001、后端 5001。4174 依旧是静态只读设计预览，不代理真实账号、数据库或音乐请求，503 属于预期。

可选设置独立强随机 `MUSIC_RECONCILE_SECRET`，由可信调度器向 `POST /api/music/reconcile` 发送同名 Bearer 凭证；一次最多核对 20 个已知上游编号的未结算平台任务。此轮只实现受保护入口，没有创建线上调度或 Cron。未配置调度时由用户打开任务后查询、手动刷新触发结算；自定义任务不托管用户 Key，不能在关闭会话后由服务端独立查询。

## 验证与发布

后端单测覆盖字段和版本校验、未知提交、收费请求不重发、平台与自定义配置隔离、所有者隔离、地址/DNS/TLS 边界、结果格式及接口权限。前端测试覆盖自动时长、五版本、自定义模型、凭据存储和下载边界。

`supabase/tests/music_generation.sql` 在隔离 PostgreSQL 中验证真实事务、每首 2 积分、重复调用、失败退款、余额不足与补结算、权限；测试数据全部回滚。浏览器验收使用实际新版构建、Flask 路由、PostgREST 网关及本机 PostgreSQL，服务商和音频均为合成数据；图像接口另外模拟验证预览超时和重试。结果位于本地 `artifacts/music-generation/`。这不等于真实 APIMart 账号、计费或全部第三方音乐接口已验收。

本轮不提交、不推送、不部署、不修改线上数据库或环境变量。Git HEAD 早于大量未提交升级工作，回退本轮代码须逐项撤回，不能 reset 或整文件恢复到 HEAD；若以后上线音乐迁移，回退网站可保留任务和流水，不能删有未结算任务的表或手工退回已完成任务。
