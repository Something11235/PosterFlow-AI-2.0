## 2026-10-23 真实查询修复与首数

用户的 Suno 任务在上游已成功返回两首，但原代码查询 `/v1/music/tasks/{task_id}` 实际 HTTP 403，随后被通用错误提示误写成“未受理”。同一 Key、同一已有任务查询 `/v1/tasks/{task_id}` 返回 HTTP 200、completed、progress=100、两首有效音频；修复后适配器直接查询真实原任务验证通过，没有重发收费 POST、没有代理修改生产积分。

APIMart 平台音乐查询现统一使用 `https://api.apimart.ai/v1/tasks/{task_id}?language=zh`；旧会话中保存的 APIMart 音乐专用查询模板也精确映射到通用路径。其他自定义服务商的地址不变，不向其他主机回退或转发 Key。参考 [通用任务查询](https://docs.apimart.ai/cn/api-reference/tasks/status)。这是当前账户的实测兼容性结论，不代表所有账户的音乐专用路径都不可用。

Suno 的公开生成参数没有 `n`、`count` 等首数选项，不提供未经证实的“只生成一首”按钮。按实际 `music[]` 展示，本次实测两首不代表固定最少两首；用户后续指定每次2网站积分，两首合计仍为2，不提供虚假的单首数量选项。Flow Music 文档明确一次一首。多请求并行不等于单请求可指定首数。

音乐界面每页允许三个任务并行，切到其他工作区后继续轮询所有进行中任务，结果按请求编号缓存。查询失败显示在对应任务旁，保留最近已知状态及真实进度；尚无进度则用不定进度条，不编造百分比。查询失败不会退款或重发生成。

## 两种服务方式

- **平台积分**：服务端使用独立的 `APIMART_MUSIC_API_KEY`，生成访问 `https://api.apimart.ai/v1/music/generations`、查询访问固定的通用任务接口。Suno 的 v6、v6-wild、v6-mini，以及 Flow Music 的 Lyria 3 Pro、Lyria 3.5 均为每次成功请求 **2 网站积分**。原来三个图像模型的端点、Key、模型和价格不变。
- **自定义API Key**：用户填写自己的完整 HTTPS 音乐生成接口、Key、鉴权方式，必要时填写任务查询地址。支持 Bearer Token 和 x-api-key。可选预置模型，或选择“自定义模型”，填写标识、可选版本，并选择 Suno / Flow Music 参数格式。不会扣网站积分。

自定义服务须兼容本页说明的异步请求和响应结构。配置一个地址不代表能兼容任意服务商的私有协议；字段或响应结构不同的接口需要另加适配器。Key、端点和鉴权配置仅在浏览器 sessionStorage 中保存，不进入数据库、草稿或日志。

## 表单与协议

Suno 提供灵感描述、自定义歌词、纯音乐，以及可选标题、风格、人声、音频格式、目标时长、排除风格、歌词改写和权重。模式切换保留各自文本，灵感模式不发送自定义模式字段；数值 0 是有效权重。没有开放上游加倍计费的 Max 模式。

Flow Music 提供风格描述、歌词、标题、目标时长、BPM 和种子。Lyria 3 Pro 使用文档的标准 Flow 路由，不发送未经确认的版本字符串；Lyria 3.5 明确发送 `version: "lyria-3.5"`。界面中的 Pro 名称对应用户选定的标准路由，服务商账号实际模型权限仍需真实联调确认。

**目标时长默认自动**：Suno 的 `duration`、Flow Music 的 `length` 在留空时完全省略，不把空串转换成 0。填写时分别校验为 10–360 秒、1–240 秒整数；目标不保证等于实际输出时长。Flow 描述/歌词 6000 字符等未由上游公开规定的限制在界面明确标为本站上限。

平台创建任务为 `POST /v1/music/generations`，从 `data[0].task_id` 取得编号；查询为 `GET /v1/tasks/{task_id}`。完成状态读取 `data.status`，不根据 100% 进度推断完成。音乐从 `data.result.music[]` 读取，保留原始 1 起始索引，不固定返回两首。音频 URL 不要求以 mp3 结尾；兼容两类时长字段及 Flow 的可选 WAV 链接。

自定义模式中的查询地址须包含一次 `{task_id}`；留空则从生成接口推导同级 `tasks/{task_id}`。两个地址须同域、HTTPS，不接受 URL 凭据或查询参数。任意自定义服务商会解析并校验公网地址，连接时固定已验证 IP、保留 TLS 主机名验证。APIMart 官方域名的标准生成/查询路由经过精确识别后，与平台模式使用同一 requests 网络路径，支持服务端受信任的系统代理；相似域名和其他路径不使用此例外。两种路径均禁止自动重定向和自动 POST 重试。

### Suno 最简使用与连接排查

选择自定义 API Key、完整生成地址 `https://api.apimart.ai/v1/music/generations`、Bearer Token；查询地址可留空。Suno v6 的“灵感成曲”把描述作为 `prompt`、发送 `custom=false`，开启纯音乐时发送 `instrumental=true`。目标时长无需填写。成功受理后由 `data[0].task_id` 获取服务商编号，再查询 `GET /v1/music/tasks/{task_id}`，以 completed/failed 为终态；结果音频在 `data.result.music[]`。

“提交结果待确认”且没有服务商编号，表示未取得可靠的受理结果，并不是正常的等待生成。刷新只能核对本站记录，不能凭本站 UUID 从上游找回未知编号。应先核对服务商调用记录，不能自动重发。Windows 网络依赖代理时，任意自定义地址的固定 IP 直连可能超时；已知 APIMart 标准接口现使用与平台模式一致的网络路径。诊断日志只记录请求方法、路径类别及异常类型，不记录 Key、请求正文或原始异常文字。

## 任务与积分

音乐采用独立 `music_jobs`，不把歌曲当图片写进 `generation_jobs`，也不受旧图片十分钟过期退款影响。

1. 一次用户意图创建一个 UUID。服务端在调用服务商之前建立持久记录；平台模式验证真实邮箱确认、账户状态和余额，并先预留 2 积分。
2. 同一所有者和请求编号只能有一条任务。参数指纹不一致返回冲突；重复 POST 返回原任务，不再次调用服务商。
3. 确认生成完成且至少存在一首有效音轨后，每次请求共结算2积分。首数由受信任查询响应确定，供输出统计使用，不作为新请求计价乘数；浏览器不能提供可信数量、价格或成功状态。
4. 预留2积分覆盖本次成功结算，不因返回多首而要求追加余额。旧版尚未结算的任务随迁移采用按次规则，刷新原任务即可结算；已结算/退款记录保留原实际流水及历史按首标记，不追溯改账。首次确认的首数仍固定，避免乱序响应改变统计。
5. 服务商明确拒绝提交，或任务查询明确返回 failed，退回预留积分；重复或乱序查询不能重复退款，也不能回退已结算终态。
6. 请求超时、5xx、异常响应及 `unknown` 不自动退款或重新提交。没有取得上游编号的提交不确定任务，需要站长根据服务商日志对账；不能保证上游不提供幂等时的端到端 exactly-once。

平台凭据不受浏览器自定义地址或 Key 影响。数据库公开包装函数为 invoker；原子积分写入和读取权威 Auth 状态由 private 中的窄接口执行，固定空 search_path、撤销 PUBLIC/anon/authenticated 执行权，仅 service_role 可调用。表启用 RLS，前端无直接读写权限。自定义任务按认证身份、Key 与完整服务配置的不可逆摘要隔离；修改服务配置后不会混入另一服务商的任务。

## 播放、下载与保存范围

页面展示任务列表、真实状态、试听控件、歌词、音频下载和可选 WAV 下载。播放器和下载直接读取服务商返回的 HTTPS 媒体，外部请求不携带本站或服务商鉴权头。下载在浏览器流式读取，60 秒超时、80 MiB 内存预算，拒绝 HTML/JSON 错误内容；失败时可打开音频链接自行保存。

后端不转存音频，不把音乐套入原图片 12 小时清理策略。任务表保存归属摘要、请求指纹、模型版本、任务编号、状态、计费和时间，不保存媒体 URL 或 Key。新增 music_prompt_history 单独保存近7天的提示词/歌词及白名单基础文本参数，复用原每小时清理任务；过期只清理文本，不删任务或流水。音频临时保留72小时，页面提醒及时下载；任务记录不代表音频永久可取。旧任务未存文本，不能补造历史。

当前页面草稿仍只存内存，刷新清空；模型、参数与草稿导出均不包含服务配置。音乐任务可凭原编号在刷新后恢复，自定义模式需重新使用原服务配置；更换身份/服务配置、卸载组件或页面不可见时停止相应轮询。切换创作工作区不停止轮询，页面停止等待不等于取消上游任务。

## 本地启用

1. 正式候选继续使用原付费项目的云端变量，不复制整份 `.env`。本地历史测试配置仍独立，不上传。
2. 空开发库须先按顺序应用既有基础迁移，再应用音乐迁移 `supabase/migrations/20261022164535_music_generation.sql` 和后续权限修复。已有库应核对迁移记录、只补缺失项，不要重跑已有生产迁移。
3. 服务端配置 `SUPABASE_URL`、`SUPABASE_SERVICE_ROLE_KEY`（或现有 Secret Key 别名）。平台音乐另配 `APIMART_MUSIC_API_KEY`，不能使用 VITE_ 前缀。
4. 登录能力使用浏览器安全的 VITE_SUPABASE_URL、VITE_SUPABASE_ANON_KEY / PUBLISHABLE_KEY。平台模式须登录并验证邮箱；自定义模式可使用访客 Key，但仍需要音乐任务数据库就绪。
5. 运行开发前端 3001、后端 5001。4174 依旧是静态只读设计预览，不代理真实账号、数据库或音乐请求，503 属于预期。

可选设置独立强随机 `MUSIC_RECONCILE_SECRET`，由可信调度器向 `POST /api/music/reconcile` 发送同名 Bearer 凭证；一次最多核对 20 个已知上游编号的未结算平台任务。此轮只实现受保护入口，没有创建线上调度或 Cron。未配置调度时由用户打开任务后查询、手动刷新触发结算；自定义任务不托管用户 Key，不能在关闭会话后由服务端独立查询。
