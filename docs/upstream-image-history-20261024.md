# 利用上游图片作为历史记录的评估

核对日期：2026-10-24。本次核对公开任务查询文档和本站交付代码，没有新建图片图库或变更Storage保存策略。

可以做“临时图片历史”：本站按账号保存任务编号/模型/创建时间，用户打开历史时，服务端验证账号归属，再用该任务编号查询上游图片URL；图片直接由上游返回给浏览器，避免为这个历史列表再复制一份大图到Supabase。参考[任务查询接口](https://docs.apimart.ai/cn/api-reference/tasks/status)，结果URL有过期字段，不能当永久托管。用户此前任务页提示过资源临时保留72小时，实际具体图片应以返回的过期时间/可访问性为准，不保证所有图片统一永久可用。

当前情况：新增模型走APIMart，但原三个GPT图片模型仍使用原服务方，无法凭APIMart任务日志为它们恢复图片。本站新增模型当前完成后还会下载并转存Supabase，用已有鉴权、缩略图、预览、备用下载和画布流程交付；只添加临时历史入口不会自动消除这部分现有Storage消耗。

共享的平台Key对应所有网站用户，不能把站主后台“最近生成图片”列表直接公开。必须只从本站验证过归属的任务记录取结果；上游Key保留服务端，客户端不能传任意task_id横向查询别人的图片。任务元数据仍需少量数据库容量和请求，不应宣称零Supabase用量。自带Key模式还需沿用其会话配置摘要隔离，不能串到平台Key历史。

建议：保留近七天提示词历史，另加“临时图片”标签，显示可查看期限、立即下载、过期状态；仅列出仍可访问的新增模型任务。若用户希望彻底停止大图转存，需要另行调整原图/缩略图/下载/画布的交付适配，并重新验证此前跨网络下载问题，不能直接删除存储代码。此项目前是可行方案说明，尚未开发或上线，等待用户选择是否采用临时图片历史及对应保存策略。
